# iAgentBench - Dynamic Benchmarking for Information Seeking Agents

A Python repository for benchmarking Information Seeking Agents (ISA) with integrated indexing, evaluation, and output management.

## Installation

1. Clone the repository and navigate to it:
   ```bash
   git clone <repository-url>
   cd iAgentBench
   ```

2. Create a conda environment (Python 3.9-3.12 required):
   ```bash
   conda create -n iagentbench python=3.12 -y
   conda activate iagentbench
   ```

3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

4. Configure `settings.yaml` with your LLM API keys and model settings:
   ```bash
   # Copy the example configuration file
   cp settings.yaml.example settings.yaml
   
   # Edit settings.yaml and replace YOUR_BEDROCK_API_KEY_HERE with your actual Bedrock API key
   # Or set the AWS_BEARER_TOKEN_BEDROCK environment variable
   ```

**Note:** This version of iAgentBench requires AWS Bedrock for LLM operations. Ensure you have AWS credentials configured and access to Bedrock models. The `settings.yaml` file is gitignored to prevent accidentally committing API keys.

## Usage

### Basic Usage

```bash
# Single query (default keyword: "local")
python cli/main.py "your keyword here"

# Options: --verbose, --project-root PATH, --searxng-url URL
```

### Batch Processing

Process multiple queries from a JSONL file with parallel workers:

```bash
# Basic batch processing (default: 4 workers)
python cli/main.py --batch input/queries.jsonl

# Custom options
python cli/main.py --batch input/queries.jsonl --batch-name my_batch --max-workers 8 --no-resume
```

**Features:**
- Parallel processing with `--max-workers` (default: 4)
- Adaptive throttling for rate limit handling
- Resume functionality (skips completed queries by default)
- Progress logging to `batch_progress.log`

**JSONL Format:** Each line is a JSON object with a `query` field:
```json
{"query": "example query 1", "display_query": "Example Query 1"}
```

**Paths:**
- Input: `input/keywords/{keyword}/` (single) or `input/{batch_name}/keywords/{query}/` (batch)
- Output: `output/{keyword}/{timestamp}/` (single) or `output/{batch_name}/{query}/{timestamp}/` (batch)

### Output Structure

Each run creates `output/{keyword}/{timestamp}/` containing:
- `graphs/`: Parquet files (entities, relationships, communities, etc.)
- `logs/`: API call logs and pipeline logs
- `interactive_graph.html`: Graph visualization
- `community_details.json`: Structured community information
- `operational_metrics.txt`: API calls, tokens, errors
- `view_graph.ipynb`: Jupyter notebook for exploring results
- `curated_artifacts/`: Generated by `cli/curate_artifacts.py`
- `generated_artifacts/`: Generated by `cli/generate_qa.py`

### Post-Run Tools

**Curate Artifacts:**
```bash
# Single run or recursive batch processing
python cli/curate_artifacts.py "output/keyword/timestamp" [--recursive] [--input-root PATH]
```

Creates `curated_artifacts/` with:
- `curated_llm_package.json`: Structured package with source documents, connector relations, and communities
- `entities_pruned.parquet` / `relationships_pruned.parquet`: Pruned graph data
- `curated_config.json`: Configuration and traceability info

**Generate QA Pairs:**
```bash
python cli/generate_qa.py "output/keyword/timestamp" [--judge-model MODEL] [--verbose]
```

Generates cross-community QA pairs with multi-judge verification (default: 3 judges). Outputs:
- `qa_pairs_passed.json`: Only candidates passing all judges
- `qa_pairs_all.json`: All candidates with judge audits

## Configuration

The `settings.yaml` file contains all GraphRAG configuration (LLM settings, input/output settings, workflow settings). See the [GraphRAG documentation](https://microsoft.github.io/graphrag/config/yaml/) for full configuration options.

## AWS Bedrock Integration

This repository has been modified to work with **AWS Bedrock** for all LLM operations. The codebase includes custom modifications to GraphRAG to enable Bedrock integration:

- **Bedrock API Integration**: Custom client implementation in `src/qa_generation/bedrock_client.py` with retry logic and throttling handling
- **GraphRAG Modifications**: Modified GraphRAG indexing pipeline (`src/graphrag_indexer.py`) to use Bedrock models via LiteLLM provider
- **API Monitoring**: Built-in logging and monitoring of Bedrock API calls with consolidated logs in `logs/bedrock_api_calls_consolidated.jsonl`

**Requirements:**
- AWS account with Bedrock access
- AWS credentials configured (via AWS CLI, environment variables, or IAM role)
- Bedrock models enabled in your AWS region (default: `us-east-1`)

Configure your Bedrock models in `settings.yaml` using the `bedrock` model provider.

## Self-Contained Design

This repository is fully self-contained with all GraphRAG code included in `src/graphrag/`. No external dependencies or paths required.

## Notes

The `lancedb/` directory in the output folder stores vector embeddings. It's excluded from organized outputs but remains in the root `output/` directory if needed for GraphRAG query/search features.

## Troubleshooting

**Import Errors:**
- Ensure dependencies are installed: `pip install -r requirements.txt`
- Run from project root directory
- Python path is handled automatically by CLI

**GraphRAG Internal Import Errors:**
- Verify `src/graphrag/` directory structure is intact
- Python path is handled by `graphrag_indexer.py`

**Missing Output Files:**
- Check logs in `output/{keyword}/{timestamp}/logs/`
- Verify input directory has files
- Check `operational_metrics.txt` for errors
